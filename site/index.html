[WHAT I OWNED]

Coinme / Polygon Labs

The product: a crypto widget that other companies, like fintech and wallet apps, put inside their own iPhone, Android and web apps. Each company sees it in its own colours and with its own set of features, but it is a single product underneath.

I joined in 2024 through Endava, as part of a frontend team of 7–10 people. When Polygon Labs acquired Coinme, they hired me directly in February 2026. Here are four pieces I owned or shaped, starting with the biggest.

01
I started it · I led it Design system · 2025–2026

One design system that every partner can rebrand

?The problem

Every company that embeds the widget wants it to look like their own app. If each one needed custom code, the team would end up maintaining a dozen slightly different products.

✎What I did

  • Started the component library on day one and looked after it for two years.
  • Designed how branding works: a partner sends only the colours and styles they want to change, and every screen updates. Nobody touches the code.
  • Built 13+ of its 34 components, including an interactive price chart you can drag your finger across.

★What came of it

  • Every screen of the product, on all three platforms, runs on it.
  • 137 releases without partners ever having to fork it.
  • New partners get their brand through configuration, not a project.
for engineers: how it works
Setup.
  • One React Native codebase rendering iOS, Android and web (react-native-web)
  • Tooling, Storybook, an Expo example app, the React Native 0.77 upgrade
Theming.
  • Design tokens, dark mode and a "host theme wins" deep merge, so a partner sends a partial theme
  • Partners override tokens, never components, which keeps the contract small and stable
Components.
  • Stacked bottom sheets, OTP input, swipeable tabs, interactive SVG price chart (Reanimated, Gesture Handler)
  • Separate web and native implementations where the platforms really differ, one API on top
Icons.
  • A cross-platform icon system that ships only the current platform's SVGs in each bundle
02
I built it · I owned it Product flows · 2025–2026

The features that have to be right, like identity checks and cash

?The problem

Each partner needs a different mix of features: signing up, verifying identity, buying crypto with cash, cashing out at an ATM. These features handle real money and are tightly regulated, so a mistake is expensive.

✎What I did

  • Owned identity verification, including all the ways it can fail (wrong SSN, phone mismatch, declines).
  • Owned the extra anti-money-laundering checks for flagged users, and built most of ATM cash-out.
  • Wrote the crypto wallet from scratch: balances across several blockchains, sending by QR code, a live price chart.
  • Built four of the 18 connections that slot features into each partner's setup, including the one that stops flagged users before any transaction.

★What came of it

  • Live inside Trust Wallet's Cash Deposits, from the Coinme sign-in onward.
  • I cleared the last blockers before a major wallet partner's launch.
  • A small command-line tool I wrote for updating every feature at once became the team's standard.

for engineers: how it works
Orchestrator.
  • The widget reads a partner's config and mounts self-contained flow packages
  • Config sets defaults: amounts, landing screen, which networks show in which region
  • A flow never knows which partner it runs in. Everything partner-specific comes through one shared contract

Also.

  • MSW API mocking brought into Storybook and the template every new flow starts from
03
I built it Partner SDKs · 2026

Developer kits that keep card numbers out of partners' hands

?The problem

Some partners want to build their own screens but still need to collect card numbers and social security numbers. Handling that data themselves would mean heavy security audits (PCI DSS) and real risk.

✎What I did

  • Built most of the card-collection SDK, for plain JavaScript, React and React Native. Sensitive fields live in a secure vault, so raw numbers never reach partner code.
  • Built the customer-onboarding SDK for JavaScript and React Native.
  • Ran the security testing on iPhone and Android, and fixed the partner security guide where it didn't match reality.

★What came of it

  • Partners stay out of PCI DSS scope.
  • The React Native onboarding SDK went from first line of code to production v1.0 in six days, packaging and CI included.
  • Docs written for partners and for their coding agents.
for engineers: how it works
Card SDK.
  • Provider + hook API, secure fields on the vault
  • A form-validity registry built on useSyncExternalStore
Onboarding SDK.
  • An accessible masked SSN field in an iframe for the web
  • A React-free core, so Vue, Angular and vanilla JS apps can integrate
  • Example apps that keep secrets out of the bundle
Team.
  • A typed interface for phone verification let three engineers build its core, hooks and UI in parallel
  • TSDoc on every export, agent skills on the partner docs site
